# فحوصات الأمان (`npm run verify:security`)

سكربت يتأكد أن قواعد قاعدة البيانات تعمل على مشروع Supabase الخاص بالطبيب. شغّله بعد كل تغيير في قاعدة البيانات وقبل كل تسليم.

يستخدم **المفتاح العام (publishable) فقط**، ولا يستخدم المفتاح السري أبدًا. كل صف أو ملف ينشئه اسمه يبدأ بـ `__verify__` ويُحذف في نهاية التشغيل حتى لو فشل فحص.

## ماذا يفحص

**كزائر (بدون تسجيل دخول):**
1. لا يرى المقالات المسودة.
2. لا يرى الإحصائيات أو الشهادات أو العيادات المخفية.
3. لا يرى الآراء غير المنشورة.
4. لا يرى ساعات عمل العيادات المخفية.
5. لا يستطيع الإضافة في أي جدول محتوى.
6. التعديل لا يغيّر أي صف.
7. الحذف لا يحذف أي صف.
8. لا يقرأ جدول `dashboard_users`.
9. لا يستطيع رفع صورة إلى حاوية `certificates`.
10. الدالة `is_dashboard_user()` ترجع `false`.

**كطبيب (يحتاج ملف `.env.test.local`):**

11. الدالة `is_dashboard_user()` ترجع `true`.
12. يستطيع إضافة صف وتعديله وحذفه.
13. المسودة مخفية عن الزائر؛ عند النشر يُضبط `published_at` تلقائيًا ويراها الزائر.
14. يستطيع رفع صورة، وتفتح من الرابط العام، ثم يحذفها.
15. رفع ملف `.txt` إلى `certificates` مرفوض.
16. ساعات عمل يسبق فيها وقت الفتح وقت الإغلاق مرفوضة.

## طريقة التشغيل

1. تأكد أن ملف `.env` فيه `SUPABASE_URL` و`SUPABASE_KEY` (المفتاح العام).
2. أنشئ ملف `.env.test.local` في جذر المشروع (لا يُرفع إلى Git) وضع فيه بريد الطبيب وكلمة مروره:
   ```
   TEST_DOCTOR_EMAIL=...
   TEST_DOCTOR_PASSWORD=...
   ```
3. شغّل:
   ```bash
   npm run verify:security
   ```
4. بدون `.env.test.local` يعمل السكربت على الفحوصات 1 إلى 10 ويتخطى 11 إلى 16.

النتيجة سطر لكل فحص (✅ أو ❌) ثم ملخص. رمز الخروج 1 إذا فشل أي فحص.

## إذا فشل فحص

لا تنشر الموقع. أرسل مخرجات السكربت كاملة إلى المخطِّط.
