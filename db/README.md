# قاعدة البيانات — دليل إعداد عميل جديد

هذا المجلد كل ما تحتاجه لإعداد قاعدة بيانات أي طبيب جديد في Supabase، **بالنسخ واللصق فقط**: بلا MCP، وبلا أوامر، وبلا برامج على جهازك.
الوقت المتوقع: **حوالي 10 دقائق لكل عميل.**

| الملف | متى تستخدمه | ماذا يفعل |
|---|---|---|
| `01-setup.sql` | مرة لكل عميل، وأيضًا عند تحديث الملف | ينشئ الجداول والحماية وحاويات الصور. آمن لو شغّلته أكثر من مرة |
| `02-add-doctor.sql` | بعد إنشاء حساب الطبيب | يعطي حساب الطبيب صلاحية لوحة التحكم |
| `03-check.sql` | في النهاية، وبعد أي تعديل | فحص صحة: كل السطور يجب أن تكون `true` |
| `90-sample-data.sql` | **للتطوير فقط** | بيانات تجريبية. لا تشغّله أبدًا على مشروع طبيب حقيقي |

## الخطوات لكل عميل

### 1) أنشئ المشروع
1. ادخل [supabase.com](https://supabase.com) ← **New project**.
2. **Name:** اسم واضح، مثل `dr-sara-alamin`.
3. **Database Password:** اضغط **Generate a password** واحفظها في مدير كلمات المرور. لن تحتاجها يوميًا، لكنها ضرورية للنسخ الاحتياطي.
4. **Region:** أقرب منطقة لمرضى الطبيب، مثل `Frankfurt` أو `Mumbai` للخليج. لا يمكن تغييرها لاحقًا.
5. اضغط **Create new project** وانتظر حتى يجهز (دقيقة أو دقيقتان).

> **من يملك الحساب؟** حسب الـ PRD، يجب أن يكون المشروع ملك الطبيب. الأفضل أن يُنشئ الطبيب حساب Supabase بنفسه ويضيفك عضوًا (**Organization → Team → Invite**)، أو أن تنقل المشروع إليه عند التسليم.

### 2) شغّل ملف الإعداد

> ⚠️ في SQL Editor، تأكد أن قائمة **Role** بجانب زر Run مكتوب فيها **postgres** (لكل الملفات). إن ظهر خطأ `permission denied for table users` فالسبب أن الدور ليس postgres. لا تحاول إصلاحه بـ GRANT.
1. القائمة اليسرى ← **SQL Editor** ← **New query**.
2. افتح `01-setup.sql` وانسخه **كله** (Ctrl+A ثم Ctrl+C) والصقه.
3. اضغط **Run** (أو Ctrl+Enter).
4. إذا ظهر تحذير **"destructive operations"** فاضغط **Run this query**. الملف يحذف قواعده هو فقط ويعيد إنشاءها فورًا.
5. النتيجة المتوقعة: **Success. No rows returned**.

### 3) أغلق التسجيل العام (مهم جدًا للأمان)
1. **Authentication** ← **Sign In / Providers**.
2. في الأعلى أطفئ **Allow new users to sign up**.
3. تأكد أن **Email** مفعّل كطريقة دخول.
4. اضغط **Save**.

> بدون هذه الخطوة يستطيع أي شخص إنشاء حساب. ومع ذلك فالملف يحميك بطبقة ثانية: لا أحد يستطيع التعديل إلا من في جدول `dashboard_users`. لكن أغلق التسجيل دائمًا.

### 4) اضبط رابط الموقع
1. **Authentication** ← **URL Configuration**.
2. **Site URL:** رابط موقع الطبيب، مثل `https://dr-sara.com`. وقبل ربط الدومين ضع رابط Cloudflare المؤقت.
3. اضغط **Save**.

### 5) أنشئ حساب الطبيب
1. **Authentication** ← **Users** ← **Add user** ← **Create new user**.
2. **Email:** بريد الطبيب الحقيقي.
3. **Password:** كلمة مرور قوية (16 حرفًا أو أكثر). أعطها للطبيب بطريقة آمنة، ولا ترسلها في نفس الرسالة مع البريد.
4. ضع ✔ على **Auto Confirm User**.
5. اضغط **Create user**.

### 6) أعطِ الطبيب صلاحية اللوحة
1. **SQL Editor** ← **New query**.
2. افتح `02-add-doctor.sql`، وغيّر **البريد فقط** في السطر المكتوب بجانبه `<<< CHANGE THIS`.
3. الصق ثم اضغط **Run**.
4. النتيجة: جدول فيه بريد الطبيب. وإذا ظهر خطأ فهو يشرح السبب: نسيت تغيير البريد، أو الحساب غير موجود.

### 7) افحص كل شيء
1. **SQL Editor** ← **New query** ← الصق `03-check.sql` ← **Run**.
2. يجب أن تكون **كل** السطور `ok = true`.
3. إذا كان أي سطر `false`: شغّل `01-setup.sql` مرة أخرى، أو `02-add-doctor.sql` إن كان السطر الأخير.

### 8) انسخ المفاتيح للموقع
1. **Project Settings** ← **API** (أو **API Keys**).
2. انسخ:
   - **Project URL** ← `SUPABASE_URL`
   - **Publishable key** (يبدأ بـ `sb_publishable_`، وفي المشاريع القديمة اسمه **anon public**) ← `SUPABASE_KEY`
3. ضعهما في ملف `.env` على جهازك للتطوير، وفي متغيرات Cloudflare للنشر.

> ⛔ **لا تنسخ أبدًا** مفتاح **Secret key** (`sb_secret_…`) أو `service_role`. هذا المفتاح يتجاوز كل الحماية، والموقع لا يحتاجه إطلاقًا.

### 9) (اختياري) فعّل المصادقة الثنائية لحسابك أنت
**Account** ← **Security** ← **Multi-factor authentication**. حسابك يصل لعشرات المشاريع، فحمايته أهم من أي شيء.

## قائمة سريعة للنسخ (Checklist)

```
[ ] 1 مشروع جديد + حفظ كلمة مرور القاعدة + المنطقة الصحيحة
[ ] 2 تشغيل 01-setup.sql ← Success
[ ] 3 إطفاء Allow new users to sign up
[ ] 4 Site URL = رابط الموقع
[ ] 5 إنشاء مستخدم الطبيب (Auto Confirm)
[ ] 6 تشغيل 02-add-doctor.sql بعد تغيير البريد
[ ] 7 تشغيل 03-check.sql ← كل السطور true
[ ] 8 نسخ URL و anon key إلى .env / Cloudflare (ليس service_role)
```

## قواعد الأمان باختصار

- **الزوار:** يقرؤون فقط المحتوى النشط والمنشور. المسودات والعناصر المخفية لا تخرج من القاعدة أصلًا.
- **التعديل:** فقط لمن هو مسجّل الدخول **و**موجود في جدول `dashboard_users`.
- **الصور:** JPEG وPNG وWebP فقط، وبحد أقصى 2 ميغابايت، والرفع للطبيب فقط.
- **جدول `dashboard_users`:** مخفي تمامًا عن الإنترنت، ولا يُعدَّل إلا من SQL Editor.
- **مفتاح anon:** آمن أن يكون في الموقع، لأن الحماية في القاعدة نفسها وليست في سرية المفتاح.

## أسئلة شائعة

**شغّلت `01-setup.sql` مرتين، هل خرّبت شيئًا؟**
لا. الملف مصمم ليُشغَّل أكثر من مرة دون أن يحذف أي بيانات.

**حدّثنا `01-setup.sql` في نسخة جديدة من الموقع، كيف أطبّقه على العملاء القدامى؟**
افتح مشروع كل عميل، والصق الملف الجديد، واضغط Run، ثم شغّل `03-check.sql`.

**المشروع متوقف (Paused)؟**
مشاريع Supabase المجانية تتوقف بعد أسبوع تقريبًا بلا نشاط. افتح المشروع واضغط **Restore project**. سنضيف لاحقًا فحصًا دوريًا يقلل هذا، دون أن يضمنه.

**الطبيب نسي كلمة المرور؟**
**Authentication** ← **Users** ← اضغط على الطبيب ← **Send password recovery**، أو أنشئ له كلمة جديدة.

**أريد إزالة صلاحية حساب قديم؟**
آخر الملف `02-add-doctor.sql` فيه أمر الحذف جاهزًا.

**ظهر خطأ `permission denied for schema storage`؟**
نادر. معناه أن المشروع قديم جدًا أو مقيّد. انسخ نص الخطأ وأرسله للمطوّر.
